# Подключение MCP

<p class="st-lead">Дайте AI-агенту доступ к связям вашего проекта.</p>

MCP-сервер SymbolTrail предоставляет восемь инструментов для исследования кода. Клиент запускает сервер и получает через stdio текстовые карточки с найденными точками и связями.

## Перед подключением

Установите зависимости исходного репозитория SymbolTrail и [соберите индекс проекта](/getting-started). MCP читает подготовленную базу, но не запускает индексацию.

## Настройка через установщик {#setup}

Из исходного репозитория инструмента выполните:

```sh
npm run setup -- --project /path/to/project --agent cursor
```

Установщик добавит MCP-сервер с именем `SymbolTrail` и скопирует навыки `graph-orchestrator` и `graph-bugfix` в проект. Исходники SymbolTrail останутся в своём каталоге.

Установщик также копирует файлы OpenSpec из каталога `openspec` исходного репозитория SymbolTrail в папку `openspec` целевого проекта:

- `config.yaml` с выбранной схемой `graph-spec`.
- `schemas/graph-spec/` с YAML-схемой и шаблонами proposal, impact, specs, design и tasks.

::: info Если OpenSpec не перенесён
При конфликте с существующими файлами или наличии `openspec/config.yml` setup пропустит весь комплект OpenSpec. Настройка MCP и навыков при этом продолжится.

Перенесите `openspec/config.yaml` и `openspec/schemas/graph-spec/` из репозитория SymbolTrail вручную или попросите агента объединить их с настройками проекта. Setup покажет источник, назначение и конфликтующие пути.

Если файлы совпадают с поставляемыми, они уже на месте и повторного переноса не требуют.
:::

При повторной настройке установщик переименовывает прежнее подключение в `SymbolTrail`, сохраняя дополнительные параметры сервера. После обновления перезапустите редактор или сессию агента, чтобы новое имя появилось в настройках MCP.

Установщик поддерживает `cursor`, `codex` и `gigacode`. Чтобы выбрать несколько клиентов, перечислите их через запятую:

```sh
npm run setup -- --project /path/to/project --agent cursor,codex,gigacode
```

Установщик сохраняет конфигурацию в проекте:

- Cursor: `.cursor/mcp.json`.
- Codex: `.codex/config.toml`.
- Gigacode: `.gigacode/setting.json`.

Список параметров установщика можно посмотреть командой `npm run setup -- --help`.

::: tip После установки
Перезапустите редактор или сессию агента. Если переместите исходный репозиторий SymbolTrail, повторите setup: конфигурация содержит пути к серверу и его зависимостям.
:::

## Ручной запуск

Чтобы запустить stdio-сервер из репозитория инструмента, выполните:

```sh
npm run mcp
```

Если JSON-клиент поддерживает `cwd`, используйте следующую конфигурацию. Замените все пути на абсолютные пути к исходникам инструмента. После выполнения npm run setup они должны подставиться автоматически:

```json
{
  "mcpServers": {
    "SymbolTrail": {
      "command": "node",
      "args": [
        "--import",
        "file:///path/to/symboltrail-source/node_modules/tsx/dist/loader.mjs",
        "/path/to/symboltrail-source/src/mcp-graph/index.ts"
      ],
      "cwd": "/path/to/symboltrail-source"
    }
  }
}
```

Чтобы выбрать конкретный индекс, передайте серверу `FILEGRAPH_SET` через настройки переменных окружения клиента. Без него сервер использует `active` из каталога индексов.

## Проверка подключения

Убедитесь, что клиент видит `find`, `callers`, `callees`, `map`, `review`, `shape`, `cycles` и `dead`.

Пример запроса агенту:

> Найди объявление foo, покажи его потребителей и прочитай текущий код найденных мест. Отдели записанные связи от предположений о выполнении.

Замените `foo` именем из своего проекта. Формат прямых вызовов описан в [справочнике инструментов](/tools).

## Навыки агента

С навыком **graph-orchestrator** агент находит неизвестные связи, выбирает адреса и читает нужный код. Навык **graph-bugfix** помогает связать диагностику и исправление с проверкой наблюдаемого поведения.

Обращайтесь к графу, когда нужно найти неизвестный переход. Уже известное тело функции или явный импорт можно читать напрямую. Чтобы связи обновлялись, держите включённым [watch](/indexing#автоматическое-обновление).
