# Решение проблем

<p class="st-lead">Начните с выбранного индекса, его актуальности и адреса символа.</p>

## MCP-клиент не видит инструменты

Убедитесь, что зависимости исходного репозитория установлены, а конфигурация указывает на существующий каталог. При использовании setup сервер называется `SymbolTrail`.

Проверьте выбранный клиент через `npm run setup -- --help`, затем повторите [подключение](/mcp#setup) и перезапустите редактор или сессию агента. После перемещения исходников инструмента настройку нужно выполнить заново.

Запуск `npm run mcp` в терминале может ожидать сообщения stdio-клиента. Для одиночного запроса без протокольного обмена используйте `npm run mcp:cli`.

## Файл или символ не найден

Проверьте по порядку:

1. Собран ли индекс нужного проекта.
2. Выбран ли он через `active` или `FILEGRAPH_SET`.
3. Относится ли `file` к корню индексированного репозитория.
4. Указано ли правильное имя участника в `repo`, если индекс многокорневой.
5. Попало ли объявление в поддержанный JavaScript/TypeScript-код.

Найдите имя через `find` и используйте возвращённый адрес. При одинаковых именах уточните файл и позицию. После создания, удаления или переименования файла пересоберите индекс.

## После правки показываются старые связи

Карточки читают последнюю опубликованную версию. Выполните разовую сборку или запустите watch:

```sh
npm run filegraph
npm run filegraph:watch
```

После сохранения watch ждёт около трёх секунд и выполняет обновление. На сетевой файловой системе событие может потеряться — тогда помогает разовая сборка.

Сниппеты и координаты не гарантируют свежесть всего графа. Текущее тело функции проверяйте в исходнике. После миграции схемы вместе с обновлением кода сервера может потребоваться переподключить MCP-клиент.

## Поиск по фразе не даёт ожидаемых результатов

Проверьте область: фильтры `file:`, `lang:`, `repo:` и явные поля запроса. В `q` должна быть сама фраза, одних фильтров недостаточно. Поиск по фразе исключает тестовые файлы; для имени из тестов используйте `name`.

Для векторной части поиска выполните сборку с `--vectors`. Первый запуск требует загрузки модели и доступного `sqlite-vec`. Подробности — в [разделе об индексации](/indexing#векторы-для-поиска).

## Задача или коммит не находятся

Поиск `issue` использует ключи из сообщений Git-коммитов. Для него нужен настроенный `issue.re` у корня индекса; первая группа регулярного выражения должна захватывать ключ. Данные из внешнего трекера не загружаются.

Для `sha` нужен полный хеш коммита. Результат строится по blame текущих файлов: коммит может быть в истории, но не иметь сохранившихся связей с текущими объявлениями. Ответ `no-issue` не означает, что задачи или коммита не существует.

## Продолжение возвращает view-changed

Изменилась версия индекса или параметры исходного запроса. Выполните `restart`, предложенный сервером, и продолжайте по новым командам `page`.

Токены продолжения не нужно собирать вручную. Копируйте их из ответа целиком вместе с оболочкой `queries`.

## Можно ли удалять всё из dead?

Сначала проверьте кандидата по исходникам. Динамический вызов, строковая регистрация или публичный экспорт могут использовать код без разрешённой индексной связи. `dead` помогает выбрать места для проверки, а тесты и проверка входов подтверждают решение.

## Все данные остаются локально?

Индекс хранится в локальной SQLite-базе; MCP работает как локальный stdio-процесс. Если вы подключаете внешний AI-клиент, передача полученных карточек и исходников зависит от настроек этого клиента и его провайдера. Первое создание векторов также требует загрузки embedding-модели.
