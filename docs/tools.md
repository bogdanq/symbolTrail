# Инструменты

<p class="st-lead">Восемь способов задать вопрос к графу кода.</p>

## Общий формат

Все инструменты принимают объект с обязательным `queries`: от одного до восьми независимых запросов **одного метода**. Они возвращают текстовую карточку, а не JSON.

```js
find({
  queries: [{ name: "foo" }, { name: "bar" }],
});
```

- `file`: путь от корня индексированного репозитория или абсолютный путь.
- `symbol`: имя объявления или экспорта в выбранном файле.
- `repo`: имя участника выбранного индекса. Используйте его, чтобы различать репозитории.
- `line` и `column`: координаты с единицы, если инструмент их поддерживает.

Пути `a.js`, `b.js` и имена `foo`, `bar` ниже условные. В реальном запросе замените их адресами своего кода.

Тот же вызов можно выполнить без MCP-клиента:

```sh
npm run mcp:cli -- 'find({ queries: [{ name: "foo" }] })'
```

## find

Найдите точку, с которой начать исследование: по имени, позиции, фразе, ключу задачи или полному SHA коммита.

```js
find({ queries: [{ name: "foo" }] });
find({ queries: [{ file: "a.js", line: 3, column: 1 }] });
find({ queries: [{ q: "parse configuration file:src/ lang:ts" }] });
```

Уточнить запрос можно параметрами `file`, `repo`, `raw`, `more`. Селекторы `issue` и `sha` используют индексированные Git-данные. Для `issue` настройте шаблон извлечения ключа из сообщений коммитов. К трекеру инструмент не обращается.

Если подходит только одно объявление, `find` может сразу открыть карточку его потребителей. `raw: true` показывает исходные совпадения без автоматического открытия и свёртки.

Поиск по `q` исключает файлы с меткой `test`; поиск по `name` включает тестовые места. Для векторной части поиска нужны [векторы](/indexing#векторы-для-поиска).

## callers

Покажите потребителей объявления: вызовы, другие роли использования и тестовые места при наличии данных.

```js
callers({ queries: [{ file: "a.js", symbol: "foo" }] });
```

Обязателен `file`. Дополнительно доступны `symbol`, `line`, `repo`, `more`. Без `symbol` инструмент показывает объявления файла и точки перехода к их использованию.

Тестовое место в ответе показывает записанную связь с тестовым кодом. Оно не говорит о том, запускался ли тест.

## callees

Посмотрите, какие вызовы находятся в теле объявления и какие определения удалось связать с ними.

```js
callees({ queries: [{ file: "a.js", symbol: "foo" }] });
```

Обязательны `file` и `symbol`. Дополнительно: `line`, `repo`, `more`. `line` помогает выбрать объявление, если имя неоднозначно, например у анонимных функций.

Если цель неизвестна, инструмент не выбирает её по похожему имени. Определение параметра callback или поля типового контракта не доказывает конкретную реализацию во время выполнения.

## map

Получите обзор папки или найдите область по фразе.

```js
map({ queries: [{ prefix: "src" }] });
map({ queries: [{ q: "configuration loading" }] });
```

Нужен `prefix` или `q`; дополнительно доступны `repo` и `more`. Карточка показывает входы в область, соседей по импортам и реэкспортам, внутренние объявления и места активных изменений по Git-данным.

По обзору удобно выбрать файлы для чтения. Условия внутри функций нужно проверять в исходниках.

## review

Сопоставьте текущий `git diff HEAD` с внешними потребителями изменённых или удалённых объявлений.

```js
review({ queries: [{ files: ["a.js", "b.js"] }] });
```

Обязателен непустой массив `files`; дополнительно доступен `repo`. Файлы одного элемента `queries` образуют общую область проверки. Потребители внутри этой области исключаются из внешних указателей.

Инструмент возвращает сырой дифф и адреса мест для проверки. Автоматического вердикта о безопасности изменения в карточке нет. Отсутствие указателя не доказывает отсутствие семантической зависимости.

## shape

Изучите записанные формы вызовов по имени.

```js
shape({ queries: [{ name: "foo" }] });
shape({ queries: [{ name: "foo", argsCount: 0 }] });
shape({ queries: [{ name: "C", isNew: true }] });
```

Обязателен `name`. Фильтры: `argsCount`, `object`, `isNew`, `form`, `file`, `repo`. Для продолжения используйте `more`.

`argsCount` считает аргументы, сохранённые в индексе. Индекс сохраняет идентификаторы, поэтому счётчик не охватывает все аргументы JavaScript-вызова с литералами или spread. Проверяйте полный вызов в сниппете и исходнике.

## cycles

Найдите циклы импортов на уровне файлов или репозиториев.

```js
cycles({ queries: [{}] });
cycles({ queries: [{ file: "a.js" }] });
cycles({ queries: [{ scope: "repo" }] });
```

Параметры необязательны: `file`, `repo`, `scope: "repo"`. Без `repo` проверяется выбранный индекс, включая межрепозиторные файловые циклы. Если указан `repo`, проверяется один участник. `scope: "repo"` выбирает циклы между репозиториями.

Цикл импорта описывает структуру зависимостей и сам по себе не доказывает ошибку выполнения.

## dead

Найдите кандидатов на неиспользуемые объявления или проверьте отдельный символ.

```js
dead({ queries: [{}] });
dead({ queries: [{ file: "a.js", symbol: "foo" }] });
```

Параметры необязательны: `file`, `symbol`, `repo`, `more`.

Перед удалением проверьте публичные экспорты, строковые регистрации, точки входа и динамические обращения. По одному лишь отсутствию индексированных потребителей нельзя решить, что код не нужен.

## Продолжение ответа

В больших карточках число показанных мест ограничено. Для следующей страницы копируйте команду `page` из ответа целиком, для перехода к точке используйте `open`.

Продолжение связано с параметрами запроса и версией индекса. Если сервер возвращает `view-changed`, выполните предложенный `restart`. Не объединяйте страницы разных публикаций.

::: tip Сначала вопрос, затем код
Для исследования обычно достаточно найти точку через `find` или `map`, уточнить неизвестную связь через `callers` или `callees`, затем прочитать найденные исходники. Проходить все инструменты для каждой задачи не нужно.
:::
