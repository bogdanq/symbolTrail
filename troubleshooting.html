title: Решение проблем description: Что проверить при пустой выдаче SymbolTrail, устаревших связях, ошибке MCP-подключения или отсутствии векторного поиска. section: Помощь

Решение проблем ​

Начните с выбранного индекса, его актуальности и адреса символа.

MCP-клиент не видит инструменты ​

Убедитесь, что зависимости исходного репозитория установлены, а конфигурация указывает на существующий каталог. Если подключение настроено через setup, сервер называется SymbolTrail.

Посмотрите параметры настройки клиента в npm run setup -- --help, затем повторите подключение и перезапустите редактор или сессию агента. Если вы переместили исходники инструмента, настройте подключение заново.

После запуска npm run mcp в терминале сервер может ждать сообщения stdio-клиента. Для одиночного запроса без протокольного обмена используйте npm run mcp:cli.

Файл или символ не найден ​

Проверьте по порядку:

  1. Собран ли индекс нужного проекта.
  2. Выбран ли он через active или FILEGRAPH_SET.
  3. Относится ли file к корню индексированного репозитория.
  4. Указано ли правильное имя участника в repo, если индекс многокорневой.
  5. Написано ли объявление в поддерживаемом JavaScript/TypeScript-коде.

Найдите имя через find и используйте возвращённый адрес. При одинаковых именах уточните файл и позицию. После создания, удаления или переименования файла пересоберите индекс.

После правки показываются старые связи ​

Карточки читают последнюю опубликованную версию. Выполните разовую сборку или запустите watch:

sh
npm run filegraph
npm run filegraph:watch

После сохранения watch ждёт около трёх секунд и выполняет обновление. На сетевой файловой системе событие может потеряться. В таком случае выполните разовую сборку.

Сниппеты и координаты не гарантируют свежесть всего графа. Текущее тело функции проверяйте в исходнике. После миграции схемы вместе с обновлением кода сервера может потребоваться переподключить MCP-клиент.

Поиск по фразе не даёт ожидаемых результатов ​

Проверьте фильтры области file:, lang:, repo: и явные поля запроса. В q должна быть сама фраза, одних фильтров недостаточно. Поиск по фразе исключает тестовые файлы; для имени из тестов используйте name.

Для векторной части поиска выполните сборку с --vectors. При первом запуске нужно загрузить модель; также должен быть доступен sqlite-vec. Подробности приведены в разделе об индексации.

Задача или коммит не находятся ​

Поиск issue использует ключи из сообщений Git-коммитов. Для него нужен настроенный issue.re у корня индекса; первая группа регулярного выражения должна захватывать ключ. Данные из внешнего трекера не загружаются.

Для sha нужен полный хеш коммита. Поиск опирается на blame текущих файлов: коммит может быть в истории, но не иметь сохранившихся связей с текущими объявлениями. Ответ no-issue не означает, что задачи или коммита не существует.

Продолжение возвращает view-changed ​

Изменилась версия индекса или параметры исходного запроса. Выполните restart, предложенный сервером, и продолжайте по новым командам page.

Копируйте токены продолжения из ответа целиком вместе с оболочкой queries. Собирать их вручную не нужно.

Можно ли удалять всё из dead? ​

Сначала проверьте кандидата по исходникам. Динамический вызов, строковая регистрация или публичный экспорт могут использовать код без разрешённой индексной связи. dead помогает выбрать места для проверки. Решение подтверждают тесты и проверка входов.

Все данные остаются локально? ​

Индекс хранится в локальной SQLite-базе; MCP работает как локальный stdio-процесс. Если вы подключаете внешний AI-клиент, передача полученных карточек и исходников зависит от настроек этого клиента и его провайдера. Первое создание векторов также требует загрузки embedding-модели.

Ошибки компиляции нативных зависимостей ​

Некоторые компоненты SymbolTrail (например, sqlite-vec для векторного поиска) содержат нативные модули, которые требуют компиляции при установке. Если вы видите ошибки сборки при npm install, проверьте наличие инструментов компиляции.

Что может понадобиться ​

Для macOS:

sh
xcode-select --install

Для Windows: Установите Visual Studio Build Tools с компонентом "Разработка классических приложений на C++".

Для Linux (Ubuntu/Debian):

sh
sudo apt-get install build-essential python3

Для Linux (CentOS/RHEL/Fedora):

sh
sudo yum install gcc-c++ make python3
# или
sudo dnf install gcc-c++ make python3

Проверка компилятора ​

Убедитесь, что C++ компилятор доступен:

sh
g++ --version
# или
clang++ --version

Если ошибки продолжаются ​

  1. Очистите кэш npm: npm cache clean --force
  2. Удалите node_modules и package-lock.json
  3. Выполните npm install заново
  4. Проверьте, что версия Node.js соответствует требованиям (20.19+)

Если проблема сохраняется, проверьте логи установки — они часто содержат конкретные указания на отсутствующие заголовки или библиотеки.
