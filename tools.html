Инструменты ​

Восемь способов задать вопрос к графу кода.

Общий формат запросов ​

Все инструменты принимают объект с обязательным полем queries, содержащим от одного до восьми независимых запросов одного метода. Инструменты возвращают текстовую карточку, а не JSON.

js
find({
  queries: [{ name: "foo" }, { name: "bar" }],
});

Общие параметры ​

ПараметрОписание
fileПуть от корня индексированного репозитория или абсолютный путь
symbolИмя объявления или экспорта в выбранном файле
repoИмя участника выбранного индекса (для различения репозиториев)
line, columnКоординаты с единицы (если инструмент их поддерживает)

💡 Примечание: Пути a.js, b.js и имена foo, bar в примерах условные. В реальном запросе замените их адресами своего кода.

Запуск без MCP-клиента ​

Тот же вызов можно выполнить через CLI:

sh
npm run mcp:cli -- 'find({ queries: [{ name: "foo" }] })'

find ​

Найдите точку входа для исследования — по имени, позиции, фразе, ключу задачи или полному SHA коммита.

js
find({ queries: [{ name: "foo" }] });
find({ queries: [{ file: "a.js", line: 3, column: 1 }] });
find({ queries: [{ q: "parse configuration file:src/ lang:ts" }] });

Параметры:

  • Обязательные: один из name, file+line, q, issue, sha
  • Дополнительные: file, repo, raw, more

Особенности:

  • Селекторы issue и sha используют индексированные Git-данные (к трекеру инструмент не обращается)
  • Если подходит только одно объявление, find может сразу открыть карточку его потребителей
  • raw: true показывает исходные совпадения без автоматического открытия и свёртки
  • Поиск по q исключает файлы с меткой test; поиск по name включает тестовые места
  • Для семантического поиска по q нужны векторы

callers ​

Покажите потребителей объявления — вызовы, другие роли использования и тестовые места (при наличии данных).

js
callers({ queries: [{ file: "a.js", symbol: "foo" }] });

Параметры:

  • Обязательные: file
  • Дополнительные: symbol, line, repo, more

Особенности:

  • Без symbol инструмент показывает объявления файла и точки перехода к их использованию
  • Тестовое место в ответе показывает записанную связь с тестовым кодом, но не говорит, запускался ли тест

callees ​

Посмотрите, что вызывается внутри объявления и какие определения удалось связать с вызовами.

js
callees({ queries: [{ file: "a.js", symbol: "foo" }] });

Параметры:

  • Обязательные: file, symbol
  • Дополнительные: line, repo, more

Особенности:

  • line помогает выбрать объявление, если имя неоднозначно (например, у анонимных функций)
  • Если цель неизвестна, инструмент не выбирает её по похожему имени
  • Определение параметра callback или поля типового контракта не доказывает конкретную реализацию во время выполнения

map ​

Получите обзор папки или найдите область по фразе.

js
map({ queries: [{ prefix: "src" }] });
map({ queries: [{ q: "configuration loading" }] });

Параметры:

  • Обязательные: prefix или q
  • Дополнительные: repo, more

Особенности:

  • Карточка показывает: входы в область, соседей по импортам и реэкспортам, внутренние объявления, места активных изменений (по Git-данным)
  • Удобно для выбора файлов для чтения
  • Условия внутри функций нужно проверять в исходниках

review ​

Сопоставьте текущий git diff HEAD с внешними потребителями изменённых или удалённых объявлений.

js
review({ queries: [{ files: ["a.js", "b.js"] }] });

Параметры:

  • Обязательные: непустой массив files
  • Дополнительные: repo

Особенности:

  • Файлы одного элемента queries образуют общую область проверки
  • Потребители внутри этой области исключаются из внешних указателей
  • Инструмент возвращает сырой дифф и адреса мест для проверки
  • Автоматического вердикта о безопасности изменения нет
  • Отсутствие указателя не доказывает отсутствие семантической зависимости

shape ​

Изучите записанные формы вызовов по имени функции.

js
shape({ queries: [{ name: "foo" }] });
shape({ queries: [{ name: "foo", argsCount: 0 }] });
shape({ queries: [{ name: "C", isNew: true }] });

Параметры:

  • Обязательные: name
  • Фильтры: argsCount, object, isNew, form, file, repo
  • Дополнительные: more

Особенности:

  • argsCount считает аргументы, сохранённые в индексе
  • Индекс сохраняет идентификаторы, поэтому счётчик не охватывает все аргументы JavaScript-вызова с литералами или spread
  • Проверяйте полный вызов в сниппете и исходнике

cycles ​

Найдите циклы импортов на уровне файлов или репозиториев.

js
cycles({ queries: [{}] });
cycles({ queries: [{ file: "a.js" }] });
cycles({ queries: [{ scope: "repo" }] });

Параметры:

  • Все необязательные: file, repo, scope

Особенности:

  • Без repo проверяется выбранный индекс, включая межрепозиторные файловые циклы
  • Если указан repo, проверяется один участник
  • scope: "repo" выбирает циклы между репозиториями
  • Цикл импорта описывает структуру зависимостей и сам по себе не доказывает ошибку выполнения

dead ​

Найдите кандидатов на неиспользуемые объявления или проверьте отдельный символ.

js
dead({ queries: [{}] });
dead({ queries: [{ file: "a.js", symbol: "foo" }] });

Параметры:

  • Все необязательные: file, symbol, repo, more

Особенности:

  • Перед удалением проверьте: публичные экспорты, строковые регистрации, точки входа, динамические обращения
  • По одному лишь отсутствию индексированных потребителей нельзя решить, что код не нужен

Продолжение ответа ​

В больших карточках число показанных мест ограничено.

Для навигации:

  • Следующая страница: копируйте команду page из ответа целиком
  • Переход к точке: используйте команду open

💡 Важно: Продолжение связано с параметрами запроса и версией индекса. Если сервер возвращает view-changed, выполните предложенный restart. Не объединяйте страницы разных публикаций.

💡 Сначала вопрос, затем код

Для исследования обычно достаточно:

  1. Найти точку через find или map
  2. Уточнить неизвестную связь через callers или callees
  3. Прочитать найденные исходники
